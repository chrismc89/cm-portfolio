Application 00 — Featured Build

PM Agent

Agentic AI project management system — MCP · FastAPI · 3 AI surfaces
Production · Deployed
FastAPI (Python) MCP Server (30 tools) AWS App Runner Docker → ECR PostgreSQL + pgvector Terraform IaC Anthropic Claude Amazon Bedrock

An agentic AI assistant for program and delivery managers built around a real PM mental model: ingest delivery data → score it deterministically → layer LLM judgment on top → expose 30 tools via MCP to whichever AI surface the user already works in. Works natively inside Claude Desktop, ChatGPT (custom GPT), and Microsoft 365 Copilot.

  • 30 MCP tools across 4 role-based personas — Program Manager, Product Manager, Product Owner, Shared — each with a distinct tool visibility set.
  • 10-layer pipeline: Jira ingest → normalization → PostgreSQL → deterministic risk engine (Tier 1, always on) → LLM judgment (Tier 2, on demand) → analysis modules → synthesis → Core Agent API → MCP/OpenAPI/Copilot adapters → AI surface.
  • Audited LLM adapter — every Tier-2 call passes a 4-step chain in code: kill switch → governance approval → PII sanitization → audit log. Graceful degradation to Tier-1 rules on any failure.
  • NIST AI RMF 1.0 + PMI-CPMAI governance alignment — explainability, human oversight, data minimization, and lifecycle controls designed in at the architecture level.
  • Three AI surfaces: Claude (MCP — stdio + Streamable HTTP), ChatGPT (custom GPT via OpenAPI action), Microsoft 365 Copilot (declarative agent via Teams).
  • Terraform IaC — ECR repo, App Runner service, EventBridge nightly batch rescore, all declaratively managed.

Application 01

CareerIQ

Personalized AI career-intelligence web app
Production · Deployed
AWS Lambda S3 CloudFront Cognito (OAuth2/PKCE) SSM Parameter Store KMS Anthropic API

Five prompt-configured AI modules — JD fit/gap scoring & resume tailoring, company research, application-strategy planning, interview prep, and profile management — served from a single-page app on AWS serverless infrastructure with a live Claude API integration.

  • OAuth2/PKCE authentication via Cognito; invite-only access enforced end to end.
  • KMS-encrypted secrets management — API key stored as an SSM SecureString, never hardcoded or client-side.
  • Live LLM integration — Lambda proxy calls Anthropic API directly; model-string cutover handled after mid-cycle model retirement.
  • Solo-diagnosed a full CORS/auth debugging arc across 9 build sessions — root causes included stale IAM policy, duplicate CORS headers, API Gateway stage-prefix mismatches, resolved by moving to a Lambda Function URL.
Scope note: 5 prompt-configured modules — not a multi-agent system. No inter-module handoff or autonomous planning.
Application 02

Delivery Insights

Multi-methodology delivery-analytics platform
Production · Deployed
Azure Static Web Apps Entra External ID (MSAL.js/PKCE) Key Vault Table Storage GitHub Actions CI/CD

Turns Jira exports into earned-value metrics (SPI/CPI/EAC), flow metrics, and ranked delivery-risk signals across Scrum, Kanban, SAFe, and PMI methodologies — a single tool that speaks four delivery frameworks' native vocabulary.

  • Zero-data-egress design — client Jira data is processed and never persisted outside the customer's own tenant boundary.

Application 03

Northline (dev codename: Waypoint)

Program/PI health dashboard with deterministic risk engine
Active Development
FastAPI + PostgreSQL Next.js 16 / React 19 / TypeScript Azure Container Apps Entra ID (EasyAuth) Bicep IaC pytest + Hypothesis

Ingests Jira data (API pull or CSV/XLSX upload) and runs it through a 9-rule deterministic risk engine producing typed, severity-scored findings — plus Monte Carlo forecasting, a Gantt roadmap view, and a stakeholder-analysis module.

  • Parallel LLM orchestration — 8 independent analysis sections execute concurrently via asyncio.TaskGroup, multiplexed onto one SSE stream with per-section timeout/error isolation.
  • Human-in-the-loop regeneration — any of the 8 sections can be re-run independently after review, without re-running the rest.
  • Multi-provider LLM abstraction — Azure OpenAI, OpenAI, and Claude behind one common adapter interface, swappable via env var.
  • Property-based backend testing (pytest + Hypothesis) — a materially more rigorous QA posture than most portfolio-stage projects.
Scope note: parallel LLM orchestration, not multi-agent AI — no section reads another's output; no autonomous planning or LLM-driven tool use in the orchestrator.
Application 04

Paceline

Engagement-health signals engine, for agencies & consultancies
Working Prototype
CloudFront + S3 (SPA) Cognito PKCE API Gateway + Lambda S3 JSON persistence

Computes EVM-style engagement metrics (CPI/SPI/EAC/PAC) and fires deterministic signals — revenue at risk, margin erosion, schedule slip, team over-burn, retainer over-service — for firms running multiple client engagements concurrently.

  • Fully AWS-native static SPA with same-origin /api/* surface backed by API Gateway + Lambda, single JSON-document-per-firm persistence in S3.
  • In active development: an evidence panel that traces every fired signal to its driving metric, phase, and team member.
  • A grounded "Ask Pacer" assistant scoped to answer only from computed evidence — not general-purpose chat.
Scope note: working prototype in active development — distinguished deliberately from CareerIQ and Delivery Insights (both production).
Application 05

Keel Watch

Contract renewal risk agent for SMB agencies — MCP · AWS Bedrock · Evidence-grounded output
Pilot-Ready · Design Partner Pending
Node.js (CommonJS) AWS Bedrock (Claude) MCP Server (stdio + HTTP) pdf-parse OpenAI-compatible Azure Container Apps @modelcontextprotocol/sdk

Reads a signed contract (PDF) and a client email thread, determines whether a renewal window is closing on a relationship that’s gone quiet, and delivers two cited work-products — a one-page renewal-risk brief and a draft outreach email. Every factual claim traces back to a specific clause or dated email via a structured evidence ledger. Nothing sends without human sign-off; low-confidence reads are surfaced, never smoothed over.

  • Evidence ledger architecture — every claim in the output cites a sourceRef (contract clause + page, or email date + excerpt); ungrounded assertions are structurally impossible, not just prompted against.
  • MCP tool wrapper — the entire pipeline is exposed as a callable check_contract_renewal_risk tool so any MCP-compatible AI agent can invoke it mid-conversation, without a human at the CLI.
  • Deliberate standalone architecture — intentionally decoupled from the enterprise Paceline SignalCore engine (gated on an IP opinion letter); pilot logic is single-purpose, disposable, and independently validated with 33 passing tests.
  • Provider-agnostic LLM layer — same pipeline runs against AWS Bedrock (default) or OpenAI/Azure OpenAI via a swappable llmClient dependency, selected per-call or via env var.
  • Full feasibility & brand system built — SMB go-to-market study, pricing model, compliance posture (no auto-send, data isolation, legal-disclaimer requirements), and a KeelAI product family brand identity completed before commercial engagement.
Scope note: pilot-ready pipeline — 33/43 tasks complete, all technical build done. Remaining steps are process (design partner engagement, delivery, debrief). Positioned as the first standalone product in the KeelAI family, not an enterprise-CLM feature.
Shared Service

Investigator Agent — Grounded Recommendation Layer

Deployed service backing Paceline and Northline as host apps
Deployed Service
Fastify (Node) AWS App Runner Docker → ECR DynamoDB Bedrock / Anthropic / OpenAI / Azure OpenAI

A real tool-calling agent — not a prompt wrapper. A bounded reasoning loop (reason → call tool → observe, capped at 3 calls and 20 seconds) decides what evidence to look up before it's allowed to make a recommendation, backed by a circuit breaker and a persisted audit trail.

  • Grounding enforced in code — recommendations that don't cite retrieved tool evidence are rejected and tagged ungrounded-fallback, not just prompted for.
  • Two-layer feature-gate governance between each host app and the agent — independent flags must both be true, so either app degrades gracefully if the agent is disabled.
  • Live cross-cloud migration — moving production traffic from Azure Container Apps to AWS App Runner via Docker → ECR → aws apprunner start-deployment pipeline.
  • Cross-language integration — same 3-tool contract proven against Paceline's JS/Node stack and Northline's Python/FastAPI stack.
  • Hands-on IAM/authorization debugging — diagnosed a live 403-on-write issue traced to an execution-role permission gap.
