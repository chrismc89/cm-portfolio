Executive summary

These are two codebases at different maturity levels. Historian is a well-engineered, defense-in-depth workflow and is ready for a pilot once governance is signed off and live evaluations are run. PM-Agent holds the more agentic surface: an MCP server with 30 tools and 8 write-capable tools. Its security and governance trail Historian's by roughly two release cycles.

Historian

4.1 / 5
Pilot-ready, with conditions

Historian is a constrained, prompt-chained workflow with no autonomous tool use. It has a six-layer fail-closed content gate, Fernet-encrypted quarantine with human-only release, and scoped, model-pinned egress consent. Every published claim must be grounded in a citation and pass an output guard. The supply chain is hash-locked and audited, and the audit log is a SHA-256 hash chain. It also passes ruff, mypy and pip-audit with no findings.

Biggest gap
Assurance runs on synthetic data and obedient fake models only. There is no live prompt-injection evaluation and no real-archive recall measurement.
Governance
The threat model, risk tolerances and residual-risk acceptance are unsigned drafts.

PM-Agent

2.5 / 5
Harden before multi-user use

The investigator is well bounded (a fixed three-tool sequence with time and call budgets), and a kill switch, PII and injection sanitizer, Slack HMAC check and Entra JWT validation are all in place. The weak points are identity and privilege. The MCP layer acts as a single service principal, persona filtering fails open, and roles are self-declared. A JWT library with known CVEs is pinned, and the dev compose file exposes an unauthenticated admin API on every network interface.

Biggest gap
Identity and privilege abuse on the MCP path (OWASP ASI03 / LLM06).
Governance
It has no AI RMF mapping, threat model or risk tolerances of its own, and the Historian hand-off is not consumed yet.
Bottom line. Use Historian's controls as the template for PM-Agent. Historian already solves the problems PM-Agent still has: loopback-only unauthenticated mode, hash-locked dependencies with pip-audit in CI, citation-based grounding, separated prompt rules and signed release provenance. Porting those patterns, rather than inventing new ones, is the fastest way to bring PM-Agent up.

Architecture review

In Anthropic's terms, both systems are mostly workflows (predefined code paths) rather than open-ended agents, which is the right default for this risk profile. The true agentic surface is PM-Agent's MCP server, where an external LLM host decides which of 30 tools to call.

Historian: gated, prompt-chained workflow

Each LLM step sits between deterministic controls. This is the evaluator-optimizer and guardrail pattern done well.

What works

  • Least agency. The model never chooses tools or actions. It only returns structured JSON that code validates (analysis/llm.py).
  • Separation of instructions and data. prompt_rules.py keeps shared rules that tell the model to treat archive text as data, and output passes through grounding.py and output_guard.py.
  • Human oversight at the right points. Quarantine release, egress consent and PM export approval are human-only and attributed.
  • Fail-closed defaults. Auth-disabled mode is refused on non-loopback hosts, and a missing judge verdict is recorded and downgraded instead of passed.

Architectural risks

  • One key for every encrypted surface. Rotation doesn't reduce the blast radius (H-01).
  • The judge shares a model with the generator by default, so failures are correlated (H-04).
  • Single host, in-process job state. In-flight analyses are lost on restart, and rate limiting depends on a proxy that may not exist (H-05, H-09).
  • The audit chain is not externally anchored. A host that can rewrite the chain from genesis can defeat it (H-07).

PM-Agent: API workflows plus an MCP tool surface

Red marks a trust boundary with a confirmed weakness. Dashed lines show where authorization or integrity is lost.

What works

  • A bounded investigator. It runs a fixed three-tool sequence with MAX_TOOL_CALLS = 3 and TIMEOUT_SECONDS = 20, and falls back to a template if the LLM output fails grounding. This is a textbook resource budget and circuit breaker.
  • Per-provider kill switch persisted to the database, plus an audited adapter that sanitizes every prompt and response.
  • Strict JWT validation that pins RS256, the audience and the issuer, with Slack HMAC checked using compare_digest.
  • MCP tools are annotated with readOnlyHint, and the server is stdio-local.

Architectural risks

  • Confused deputy. Every MCP user acts as one client-credentials principal, so the API can't distinguish users (P-02).
  • The investigator prompt puts instructions after untrusted evidence, with no system prompt or delimiters (P-05).
  • The LLM can write to the signal store via ingest_csv_data with no confirmation step, which is a memory and context poisoning route (P-06).
  • The hand-off contract is one-sided. Historian publishes it, but PM-Agent has no consumer, schema check or freshness check (P-11).

Workflow-to-agent roadmap

These recommendations follow Anthropic's guidance on building effective agents, writing tools for agents, context engineering and its multi-agent research system. The aim is not to turn everything into an agent. It is to add model-directed control only where the number of steps really can't be predicted, and to keep the deterministic controls that make Historian trustworthy.

Guiding rule. Anthropic recommends "finding the simplest solution possible, and only increasing complexity when needed," and says agents suit "open-ended problems where it's difficult or impossible to predict the required number of steps" (Anthropic). In both systems, the privacy gate, quarantine, consent and approvals have fixed steps and must stay as code. Investigation and gap-filling are open-ended, and that's where agency pays off.

Recommendations

R1

Fix the prerequisites before adding autonomy

An agent amplifies whatever identity and tool problems already exist. Close P-01 (JWT library), P-02 (on-behalf-of identity and fail-closed filter), P-05 (prompt structure) and P-06 (write confirmation) first. Anthropic warns that autonomy brings "the potential for compounding errors" and recommends "extensive testing in sandboxed environments, along with the appropriate guardrails" (Anthropic).

R2

Turn PM-Agent's investigator into a bounded agent loop

Keep the existing tools (check_recurrence, check_related_items, check_precedent, _get_events_around_date) and let the model choose the order and when to stop. Keep the hard limits: raise MAX_TOOL_CALLS from 3 to about 8, keep a wall-clock timeout, and keep the template fallback. After every call, return the tool result as "ground truth from the environment" so the model can judge its progress. End with structured output that lists evidence_refs for each claim (this also fixes P-04).

R3

Add a read-only evidence-gap agent to Historian

Wrap history/locate.py, timeline.py and versions.py as three or four read-only tools that work only on the cleared store, never on quarantine. The agent tries to resolve each gap from gaps_log and returns either a cited passage or "still unresolved". Its output still goes through grounding.py and output_guard.py, and egress consent must name the agent's model.

R4

Redesign the MCP tool surface for agents, not just people

Following Anthropic's tool-writing guidance, cut the 30 tools down to a smaller set with no overlap. Use namespaces such as pm_read_* and pm_propose_*, and make responses short and meaningful rather than raw dumps. Poka-yoke the arguments: resolve project_ref against known projects, replace free-text csv_content with a file reference, and use enums for categories. Anthropic reports spending "more time optimizing our tools than the overall prompt" (Anthropic).

R5

Use propose, approve, execute for every write

Write tools should return a signed proposal (a diff with an ID and an expiry) instead of acting. A separate, human-only approve(proposal_id) path, through the API or MCP elicitation, carries out the change under the user's own token. This is the same pattern as Historian's quarantine release and export approval, applied to PM-Agent.

R6

Engineer the context, not just the prompt

Give each agent a system prompt split into sections (background, instructions, tool guidance, output format), as Anthropic's context-engineering guidance suggests. Put untrusted evidence in tagged data blocks and load it on demand through IDs ("just in time"). For long investigations, compact the running history. Historian's prompt_rules.py is a good starting point to share.

R7

Make the agent's reasoning visible and auditable

Transparency is one of Anthropic's three core principles. Log each plan, tool call, argument summary and stop reason as a trace, and send it to Historian's hash-chained audit log, or a copy of it in PM-Agent. Show the trace in the investigate response so a PM can see why a recommendation was made.

R8

Evaluate agents on transcripts, not just final answers

Extend PM-Agent's evals/ harness (35 cases) with agent tasks. Score accuracy, number of tool calls, tokens, runtime and errors, as the tool-writing guide recommends, and keep a held-out set. Add injected-content cases (H-03). Each rung on the ladder needs a passing eval before it's released.

R9

Stay framework-light

Both repos call the LLM APIs directly through thin adapters, which is what Anthropic advises: "start by using LLM APIs directly" and make sure you understand any framework's internals. Implement the loop in about 100 lines in ILLMAdapter or AuditedLLMAdapter instead of adopting a heavy orchestration framework. Revisit only if you reach L4.

R10

Treat multi-agent as optional, and only after L3 works

Anthropic's research system shows orchestrator-workers outperforming a single agent on broad tasks, but at much higher token cost (Anthropic). If you get there, expose Historian to PM-Agent as a read-only worker over the approved export (after P-11). Delegate with explicit goals and output formats, and have the worker return condensed, cited summaries.

What must stay deterministic

  • Historian's six-layer gate, quarantine release and the random audit with auto-suspend.
  • Egress consent and model pinning. No agent can expand its own consent or switch models.
  • Grounding and the output guard, applied to all agent output.
  • Authentication, role checks and tenant scoping, enforced in the API and never in a prompt.
  • Kill switch, budgets and stop conditions, enforced in code outside the loop.
  • PM export approval and every write approval: human-only, attributed to the user, with an expiry.

Reference loop for the PM-Agent investigator

# agent_api/investigator.py: bounded agent loop (sketch)
TOOLS = [check_recurrence, check_related_items, check_precedent,
         events_around_date, historian_lessons]          # all read-only, scoped to the user
MAX_TOOL_CALLS, TIMEOUT_S = 8, 45

async def investigate(project_ref, signal_category, scope):
    if not kill_switch.is_enabled(provider): return template_fallback(...)
    ctx = [system_prompt(rules=PROMPT_RULES, tools=TOOLS),     # instructions first
           user_task(project_ref, signal_category)]            # data goes in tagged blocks
    trace, calls = [], 0
    async with timeout(TIMEOUT_S):
        while calls < MAX_TOOL_CALLS:
            step = await llm.next_step(ctx, tools=TOOLS)        # plan + tool_use or final
            trace.append(step.plan)                             # transparency
            if step.final: break
            result = run_tool(step.tool, step.args, scope)      # user token, not service token
            ctx.append(as_evidence_block(result)); calls += 1   # ground truth each step
    rec = parse_structured(step.final)                          # claims + evidence_refs
    if not verify_evidence_refs(rec, trace):                    # replaces substring check
        return template_fallback(..., trace=trace)
    audit.log(trace, stop_reason, calls)                        # hash-chained
    return rec

Notable strengths

These are worth highlighting in a portfolio or design review, since they go beyond common practice for agent projects.

Historian

  • A supply chain close to SLSA level 2 in spirit: --require-hashes installs, pip-audit in CI, gitleaks, SBOM and Sigstore build-provenance attestation in release.yml.
  • Consent is bound to the model. Egress consent pins the extraction, synthesis and judge model IDs, so swapping models invalidates it. AI 600-1 rarely sees this level of value-chain control.
  • Statistical assurance design. A random audit of cleared units auto-suspends egress above a miss-rate threshold, and the docs state the 29-audit sample needed for <10% at 95% confidence.
  • Honest self-assessment. The NIST mapping flags its own gaps and refuses to claim conformance, which is exactly what GOVERN 4 and MEASURE 4 ask for.
  • 748 tests passing, plus clean ruff and mypy runs across 77 source files.

PM-Agent

  • The investigator follows the "simplest thing that works" advice: deterministic tool order, hard budgets and a template fallback.
  • A kill switch exposed as an admin API and persisted, which covers MANAGE 2.4 (disengage or deactivate).
  • The audited LLM adapter applies PII redaction and injection pattern stripping to both directions of every call.
  • A production guardrail that crashes at import if auth is disabled outside dev.
  • An offline LLM eval harness (evals/) with 35 cases and scorers for citation accuracy, grounding, hallucination and run-to-run consistency, plus a run-comparison tool.
  • 442 tests in about 2.5 seconds with a clean ruff run, plus dedicated prompt-injection and sanitizer test suites.

Method and limitations

What was done

  • Both repos were cloned from GitHub at the commits shown, and the full test suites were run on Python 3.11.
  • Static analysis: ruff, mypy (Historian), bandit (medium and above) and pip-audit against the resolved dependencies.
  • Manual review of auth, LLM adapters, prompt construction, grounding, MCP tools, CI/CD, Dockerfiles and compose files.
  • Historian's NIST self-assessment was read and spot-checked against the code, not accepted as-is.

Limitations

  • The local folder on your PC couldn't be read because the device did not respond. Any uncommitted local changes aren't covered.
  • No live LLM calls, penetration test or cloud deployment review were done. Terraform in PM-Agent/infra was only skimmed.
  • Bandit's 8 SQL-injection flags in historian/history/store.py were checked and are false positives, because identifiers are composed with psycopg2.sql.Identifier.
  • Scores are expert judgment. Neither NIST nor OWASP certifies or scores conformance this way.
